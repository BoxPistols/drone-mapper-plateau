# DroneMapper v1.0 仕上げ計画 — UI/UX 最終工程と機能の取捨選択

作成日: 2026-10-30 / 対象: `main`（533b9e5）
ベースライン: `tsc` エラー0・ESLint 警告4（エラー0）・Vitest 49件全通過・JS バンドル 987KB（gzip 267KB、three.js 同梱）

---

## 0. 結論（先に読む）

- **v1.0 のコアは「まちを選ぶ → ルートを引く → 飛ばして確かめる」の1本だけ**にする。この3ステップはすでに最も作り込まれており、SimEngine・カメラ・完了演出・チェックリストは品質が高い。
- **写真・動画（Media）と飛行記録（Records）は v1.0 から外す。** どちらも「見た目は動くが中身がない」状態で、仕上げるコストが価値に見合わない（詳細は §2-B）。
- **AI アシスタントはフラグで非表示**にする。公開版（GitHub Pages）では API キーが渡されておらず、常に使えないタブが見えている。
- **飛行エリア（ゾーン）と目印（ピン）は「補助ツール」に格下げ**。今は必須ステップとして案内しているが、計画にもシミュレーションにも一切影響しない。
- 最大の UX 問題は機能不足ではなく **「案内と実装の食い違い」**（ステップ番号が3系統、ガイド文とボタン名の不一致、ヘルプが右クリック仕様を説明していない）。ここを1箇所で定義し直す。
- 工程は 5 フェーズ・目安 8〜11 人日。Phase 0（削る）→ Phase 1（動線を1本化）が最重要で、ここまでで初見ユーザーの体験は大きく変わる。

## 1. v1.0 のゴール定義

### ターゲットユーザー
1. **初見の人**（展示・デモ・営業資料で触る）: ヘルプを開かずに 3 分でシミュレーション完了まで到達できる
2. **ドローン操縦者**（現場の下見）: 建物の高さを見ながらルートを引き、KML を書き出して実機アプリに持っていける

### 完了の定義（Definition of Done）
| 指標 | 目標 |
|---|---|
| 初見ユーザーテスト（5名） | ヘルプ非参照で「都市選択 → 通過ポイント3点 → シミュレーション完了」を 3 分以内に 4/5 名が達成 |
| 案内文とボタン名の不一致 | 0 件（文言は `constants/labels.ts` に集約して検証） |
| 何も起きない UI | 0 件（ステータス変更・エリア種別など「変えても結果が変わらない」操作を残さない） |
| `tsc` / `eslint` / `vitest` | すべて緑、ESLint 警告 0 |
| JS バンドル | 500KB 以下（three.js 単体で 520KB・gzip 131KB を実測。Media 削除でほぼ半減） |
| キーボード操作 | 計画作成〜シミュレーション開始までマウスなしで完走 |
| 768px 幅 | 主要動線が完走できる（サイドバーをドロワー化） |

## 3. 目指す体験（情報設計）

### 3ステップに統一（番号は `constants/steps.ts` の1箇所で定義）

| STEP | 見出し（サイドバー／ガイド／ヘルプ共通） | 完了条件 | 画面 |
|---|---|---|---|
| 1 | **まちを選ぶ** | 都市を選択（既定: 台東区なので実質スキップ可） | マップタブ上部 |
| 2 | **ルートを引く** | 通過ポイント 2 点以上 | 飛行計画タブ。計画作成と同時に配置モードへ |
| 3 | **飛ばして確かめる** | シミュレーション完了 | 計画詳細の primary ボタン |

補助ツール（STEP 外、折りたたみ）: エリアからルート自動生成 ／ 飛行エリア・禁止区域 ／ 目印 ／ 場所検索から追加 ／ エクスポート

### タブ構成
`マップ`（STEP 1 ＋ 補助ツール） ／ `飛行計画`（STEP 2・3） ／ `AI`（キーがある環境のみ）
→ 現在の 5 タブから 2〜3 タブへ。

### 計画詳細の並び（上から）
1. 計画名（1行。パイロット・機体・日付・メモは「詳細を編集」に折りたたみ）
2. **通過ポイント**（最上部。「地図でポイントを追加」が唯一の大ボタン）
3. 飛行統計（距離・時間・最大高度・150m 警告・禁止区域警告）
4. アクション: **シミュレーション**（primary）／ エクスポート ／ ⋯（削除）

### 初回フロー（ウェルカム → 最初の成功まで）
- ウェルカムは `localStorage` で初回のみ。「使い方」から再表示可
- 「自分でやってみる」を選んだら **計画を自動作成して配置モードで開始**。地図中央に「ここをクリックしてポイントを置く」のパルス表示。2点目を置いた瞬間に「飛ばしてみる」ボタンがガイドに出る
- 初回のシミュレーションはチェックリストを **「次回から省略」付き**で出す（デモ時は従来どおりスキップ）

## 6. 判断をお願いしたい点（推奨を先に書く）

1. **Records / Media を削除してよいか** — 推奨: 削除。残す場合は「仕上げる」側に回し、最低限 (a) 動画の `videoUrl` 保存 (b) glb の実ロード (c) IndexedDB 永続化 が必要で +4〜5 人日。
2. **AI を v1.0 に含めるか** — 推奨: 含めない（公開ビルドにキーを渡さず非表示）。含めるならサーバープロキシ（Vercel/Netlify Functions 等）＋非機密フラグが前提で、クライアントに API キーを渡す選択肢は取らない。
3. **ダークモード** — 推奨: 両対応を維持しトークンへ分離。ライト固定にするなら約 100 行削除で済む。
4. **飛行前チェックリスト** — 推奨: 初回必須・2回目以降は省略可。常時必須にするなら「飛ばしてみたい」初見層の離脱を受け入れる。
